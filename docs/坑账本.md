# 坑账本

记「为什么这么做」，不记实现细节。将来重写或大改时当行为说明书；出怪问题先翻这里。

---

## 2026-08-17 手机菜单点了没反应

顶栏用了毛玻璃效果（半透明 + 背景模糊）。带这种效果的元素会把它内部的全屏弹窗「关」在自己里面——抽屉菜单本来写在顶栏里面，结果只能撑到顶栏那么高，看起来就是点了没反应、顶上多了一条白边。

**现在的处理**：抽屉和它后面的灰色遮罩必须写在顶栏**外面**，不能塞回顶栏里。以后谁给顶栏加类似的视觉效果，也别把全屏弹层放进去。

## 2026-08-17 站上图片一律自己托管

早期为了快，站上 103 张图全是直接链客户旧站（`img.venco.com.hk` 和一个 `workers.dev` 临时域名）。旧站一改版、清图片目录或换域名，新站就整片开天窗，加载快慢也完全看对方服务器。

**现在的处理**：图片全部下载到 `public/assets/img/`，数据文件里只写 `/assets/img/xxx`。以后新增图片同样先下载再用，不要直接贴外站链接。补图的脚本留在 `scripts/fetch-images.mjs`，可重复执行（已下载的会跳过）。

## 2026-08-17 关于页配图写在数据里，不写死在页面上

客户反馈「白底一堆字」不好看，关于页改成了图文交错。配哪张图、配什么小标题存在 `src/data/site.json` 的 `aboutBlocks` 里，中英文各一份。

**为什么**：以后客户想换图换标题，改 json 就行，不用动页面代码。`aboutBlocks` 按顺序和 `about` / `aboutEn` 的段落一一对应，删段落时记得同步删对应那条。

## 2026-08-17 首页 hero 手机端要有颜色，桌面端不要动

客户对比旧站后说新站首页手机端「什么都没有」——之前手机上是白色卡片压在几乎看不见的照片上，显得很空。旧站是暖米色底、文字居中、照片隐约透出来。

**现在的处理**：手机端（≤700px）hero 改成暖米色（`--warm` 变量，#f7eadf）半透明罩在诊所照片上，文字居中，两个按钮加大加饱满。**桌面端刻意保持左对齐、照片露在右边**，这是之前专门定过的（见 commit 7b6fb50），改样式时只动 `@media (max-width:700px)` 里的规则，别动外面的。

## 2026-08-17 服务页顶部的「浏览文件」按钮已删

服务页标题下面原本有个「浏览文件」按钮，点了只是跳到本页最下面的文件区，而文件区目前是空的。客户觉得多余，已删掉（中英文都删）。

**注意**：下面的「文件下载」区块本身还留着，将来客户真给文件时往 `src/data/documents.json` 的 `files` 里加就会显示。

## 2026-08-17 服务页专科列表手机端为什么不做两列

旧站手机上专科是两列图标卡。新站每张卡多了一行「N 个服务细项 · M 位相关医生」，这行字在两列的窄格子里会挤成两三行，英文版（如「10 service items · 2 related doctors」）更挤。

**现在的处理**：手机端保持一列，但给卡片加了浅青色渐变底、更大的图标白底方块和圆角阴影，视觉上有「卡片感」，同时保住那行信息。

## 2026-08-17 `www` 地址需要独立接入 Cloudflare 才能跳转

主域名能打开，不代表 `www.vencokids.com` 也会自动生效；没有 `www` 的 DNS 记录时，请求到不了 Cloudflare，后台跳转规则也就没有机会执行。

**现在的处理**：`www` 使用已代理的 DNS 记录接入 Cloudflare，再由 Redirect Rule 永久跳到主域名，同时保留原路径和查询参数。

## 2026-08-17 首页首屏不能把内容容器撑成整页宽

首页首屏虽然套了全站内容容器，但自己的宽度设置会把它撑回整个屏幕，结果大标题和正文直接贴到最左边，和旧版的居中留白完全不同。

**现在的处理**：首屏沿用全站内容宽度；桌面导航可以更宽以容纳搜索、双语切换和三级菜单，但首页文字仍保持旧版的阅读宽度和左右留白。

## 2026-08-17 繁體中文直接放在根地址

静态网站把 `/` 写成页面跳转时，会先显示一张英文等待页，部分浏览器还可能不自动继续。

**現在的處理**：繁體中文直接使用 `/`、`/services/` 等无语言前缀地址，英文保留 `/en/`；旧的 `/zh/...` 由 Cloudflare 永久跳到对应的新地址，不能再把根地址改回静态等待页。

## 2026-08-17 首頁服務卡要保留舊版的份量和回應

旧版服务区用宽版六列大卡片，图标和文字居中；鼠标移上去时卡片明显上浮、阴影加深、标题变青色，并出现「了解更多」。如果压回普通小卡片，首页会显得稀薄。

**現在的處理**：桌面端维持宽版六列和大图标，手机端改为两列；键盘聚焦也要有同样反馈，减少动画偏好的访客则不播放过渡。

## 2026-08-17 首頁底部是聯絡橫幅疊在青色頁腳上

旧版底部的辨识度来自「浅色页面—渐变联系横幅—青色页脚」三层关系，并在页脚集中放营业时间、两间诊所地址、电话和微信二维码。

**現在的處理**：联系横幅跨在页面与页脚之间，页脚按旧版分栏；真实地址、电话、WhatsApp、二维码和法律链接都继续使用现有资料。

## 2026-08-17 舊站影片地址不能原樣抄進資料檔

舊站 HTML 裡的 `&amp;` 是顯示用寫法，原樣存進新站資料後會被再次轉義，YouTube 收到錯誤參數就可能打不開；舊播放器的來源網址也不能沿用。

**現在的處理**：影片資料只存正常的 YouTube 嵌入網址；首頁凡是內容確實帶影片的文章，都顯示播放標記，點擊後進文章播放。

## 2026-08-17 Doctors 首頁要完整展示團隊

Doctors 原本是一張完整的醫生與醫護團隊總覽；如果首頁只剩「選擇科室」，訪客會以為原來的團隊頁被刪掉。

**現在的處理**：`/doctors/` 保留完整團隊總覽，每位成員再連到所屬科室的第三級頁面；不能為了增加科室層級而取代總覽。

## 2026-08-18 疫苗页内容来自诊所单张，改动前要问医生

儿童疫苗接种页原本只有一句话，客户觉得太单薄。内容现在整理自诊所自己的《強健寶寶 防疫注射》宣传单张（PDF 原件在客户手上，不在仓库里），存在 `src/data/vaccine.json`。

**两件要守住的事**：

1. **单张上医生用蓝笔划掉了「或使用退熱貼」这几个字**，三处都划了。转录时已按划掉处理，正文里没有这句。以后谁看到网上别处有这句，也不要加回来——这是诊所刻意删的。
2. **所有月龄、剂次、体温数字都是逐字照抄，不是我们编的**。要改任何一个数字，先问诊所医生，不要自己"优化"。页面底部有一句免责声明，说明资料仅供参考、不能取代医生意见，那句也别删。

英文版目前没有这块内容（单张本身是中文的），英文页还是原来那一句。

## 2026-08-19 疫苗页两块内容的主次关系

客户指出：家长第一眼想知道的是「这针防什么病」，不是「打完会怎样」。所以：

- **可預防的傳染病**是主角——每种疫苗单独一条列出来，标题下面挂着它防的病名，点开看详细后果。**按疫苗分组，不按病分组**：白喉、破傷風、百日咳本来就是同一针，拆开列反而难懂。分组是在页面里按 `vaccine` 字段自动合并的，json 里还是一病一条，不要手动去 json 里合并。
- **注射後反應及護理**收进一个折叠里，需要的人才点开。

改这块之前先想清楚谁是主角，别又倒过来。
